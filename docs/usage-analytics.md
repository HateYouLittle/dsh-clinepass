# 用量统计说明

[返回 README](../README.md) · [English](usage-analytics.en.md)

本页说明 `dsh-clinepass` 用量看板统计什么、如何计价，以及哪些数据不会被计入。

本插件是独立客户端，与 Cline 无隶属或背书关系。

## 入口

- 用量胶囊展开面板底部的「用量统计」行；
- 设置页的「用量统计」卡片：**看板** 打开看板，**主题** 切换风格。

## 数据来源

看板由 Host 侧读取 DSH 的 `ctx.sessionQuery`：

- `listSessions()` 按最新在前列出会话；
- `readSession(id)` 返回完整事件日志，包含已关闭的会话；
- 只扫描事件。看板不会自行解压归档日志，也不会让会话变为活动状态。

浏览器只收到聚合数字：不含会话 ID、标题、消息内容、工作目录或凭据。

扫描与聚合都在本地进行，计价也不需要联网：费率随插件发布，报告把该来源标为 `clinepass-catalog`。报告标注为价格来源的目录快照本身可能为诊断而刷新网关模型列表，但该请求不携带对话内容、账号 Key 或统计信息。正常推理与用量查询仍然发往你配置的网关；此外没有任何遥测或统计服务。

## 统计口径

### 计入的请求

- `dsh-clinepass` 路由上的 `assistant/message` 事件（每个对应一次已完成的模型请求）；
- 同一路由上的 `compaction/summary` 事件（即压缩请求）；
- 0.1.16 之前的 `clinepass` 路由 ID，但仅限开始时间早于 2026-09-30 UTC 的请求；之后的 `clinepass` 记录属于 DSH 原生路由，不计入。

### 不计入

- DSH 原生 ClinePass 路由及其他所有提供方；
- fork 继承的前缀（序号严格小于 `inheritedEventCount`）；
- 未进入会话日志的模型调用；
- 无法归属到本插件路由的调用（日志缺少路由头或模型 ID）——页脚会把它们计为未归属活动，不计 token 与金额；
- 没有用量记录的失败请求；它们只出现在“未结算”计数里。

### 请求时间与区间

请求开始时间取自匹配的 `step/start` 事件；缺少该键时取该会话最近一次 `step/start`，只有会话完全没有记录开始时才回退到消息事件时间。压缩摘要使用自身事件时间。区间为半开区间 `[from, to)`，按天分桶使用浏览器的 IANA 时区。

### token

- 输入、输出、缓存读取、缓存写入分别统计；
- 计费输入 = 输入 + 缓存读取 + 缓存写入；
- 用量按字段降级：某个字段存在但格式错误时只影响该字段，其他有效字段照常计入；只有输入与输出都缺失或格式错误时才计为“缺用量”，且缺用量不会被当作 0 计入估算；
- 缓存命中率 = 缓存读取 /（输入 + 缓存读取 + 缓存写入），输出 token 不进入分母；分母为 0 时显示 0.0%。

### 金额

- 每条随插件发布的记录为各分量提供一个固定费率（$/1M tokens），估算即 token × 费率，以整数微美元累加；
- 全部历史都按构建看板时生效的费率估算；
- 目录中没有可用费率的模型视为未计价：不计金额、单独计数，其金额单元格显示 **未计价** 标签。真正免费、且带有合法全零费率的记录仍按 0 计价；
- 只有至少一次请求完成计价时，导语才给出金额；否则金额位置显示 `—`，因此“无法计价”不会显示成 `$0.00`；
- 价格表不可用或等待超过四秒时，使用上一次成功的价格表；完全没有可用价格表时，区间内出现过的模型都会列为未计价；
- ClinePass 不公布按模型的月度额度，因此报告中的按模型额度字段始终为 `null`/未知，看板也不显示额度列。官方窗口百分比仍是权威值，绝不会由估算反推。

## 模型明细

每个模型行显示名称，以及请求数、输入、输出、缓存读取、金额与金额占比。金额单元格有三种状态：

- 有已计价请求时显示估算金额，即使同一行内还有未计价请求；
- `pricedRequests === 0` 且 `unpricedRequests > 0` 时显示 **未计价** 标签；
- 该行所有请求都缺用量时显示 `—`，表示这行没有可用数据，而不是“免费”。

没有金额时占比单元格显示 `—`；“另有免费或未计价模型”一行只列出真正未计价的模型。

看板的 **额度** 区域显示官方窗口百分比：窗口名称、百分比、进度条、重置时间与接近上限的标记。它在看板打开时读取一次，点击刷新时再读一次；胶囊本身在可见时每分钟轮询同一组数字。

## 主题与胶囊

- 四种风格：**寂静黑**、**石墨**（默认）、**海盐青**、**暖砂**。每种都有跟随 DSH 配色方案的深色与浅色变体。
- 唯一的开关是设置页「用量统计」卡片里的 **主题** 行。选择保存在浏览器，不写入设置文档。
- 胶囊与看板渲染所选风格；设置页保持 DSH 自身外观。
- 存在多个账号时，胶囊会在读数旁显示当前账号名称；只有一个账号时只显示读数。

## 扫描上限与性能

- 默认最多 **500 个会话**、**500,000 个事件**、**200,000 条折叠记录** 和 **12 秒**，并发读取最多 8 个会话（无法并发读取的宿主回退为串行）；
- 超出任一限制会把报告标记为不完整并给出原因（会话切片、事件预算或时间预算）；页脚还会报告因预算或上限而未读取的会话数，但不代表区间已完整覆盖；
- **扫描更多历史** 会把会话上限翻倍，最高 2,000；该选择保存在浏览器，重新打开面板仍然有效；
- 已关闭会话的折叠结果缓存在内存中，按 LRU 复用，并在每次扫描时用其持久日志版本号校验：两次打开看板之间被恢复并关闭的会话，版本号变化后会重新读取。没有版本号时，内存复用仅限五秒。活动会话的折叠结果同样有五秒复用窗口，并在关闭时重新读取；淘汰只发生在一次扫描结束时，报告始终基于该次运行实际读取的结果构建；
- 折叠结果还会持久化到 `~/.dsh/cache/dsh-clinepass/analytics-folds.v1.json`（遵循 `DSH_HOME`）：文件带版本号，上限 32 MiB，先写临时文件再改名就位，超过 30 天未重新校验的条目会在下次写入时丢弃。活动会话从不写入，被取消的扫描不写入任何内容；没有持久会话索引的宿主回退到内存缓存。缓存只保存会话 ID、模型名、token 数与时间戳——不含标题、消息文本、工作目录或凭据；
- 价格表与扫描并行构建，最多等待四秒；
- 页脚分别给出列表、扫描与计价的耗时；
- 同一次打开期间，区间终点在打开时固定，因此重新选择同一区间会先渲染上次报告并在后台重新校验；**刷新** 会强制重新扫描；
- 关闭对话框会中止正在进行的扫描；没有后台轮询。

## 契约兼容规约

看板的查询与报告由 `src/analytics-contract.ts` 中的严格编解码器在两端校验。两条规则是本仓库的既定政策：

- **新字段以可选数字或字符串传递。** 报告校验器会放行未知键，查询校验器会丢弃未知字段，因此两端同时发布时新增可选数字或字符串字段是安全的；
- **不要为枚举新增取值。** `coverage.truncation` 与模型行的 `limitNote` 是白名单校验的枚举字段，旧客户端遇到未知取值会拒绝 **整份报告**。两端未同时发布前不要扩展这些枚举。

## 已知限制

- 会话请求头不携带账号身份，因此历史无法按账号拆分；看板汇总所有已保存账号；
- 在产生用量前失败或被取消的请求，网关仍可能计费，但不会计入金额；
- 压缩摘要按请求计数，因此请求总数包含它们；
- 设备或网关时钟偏差可能把一次请求移到相邻的日期；
- 随插件发布的费率是参考数据，可能与实际账单有出入；官方百分比仍是权威值。

## 验证

`analytics-scan`、`analytics-pricing`、`analytics` 与 `analytics-fold-cache` 测试，加上客户端测试，覆盖提供方过滤、fork 截断、按字段降级、请求时间回退、缓存复用窗口、截断与预算中止、并发池、未计价模型、价格表回退、取消、分段耗时以及两个入口。全部使用合成会话与假的查询服务，不读取真实用户日志。
